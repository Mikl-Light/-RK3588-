# 磁力计干扰实测与结论（2026-10-18）

> 实测方式：SSH 远程控制实车（`mikl@100.94.102.64`，固件串口 `/dev/ttyS1` @460800），
> 通过固件 `M1~M4,DUTY,<0~1>` 命令开电机、`$T` 遥测帧读磁力计三轴 + 陀螺 gz，逐轮对照。
> 涉及固件版本：`v3.2-CFIX` → **`v3.3-MAGFIX`**。

---

## 一、一句话结论

**磁力计从头到尾都能用，只是之前被两个问题挡住了：**
1. 一个数据**冻结 bug**（读取时缺 ST2 寄存器），让磁力计数十年如一日只返回上电首帧旧值；
2. 长期误判"电机干扰是地磁 40~60 倍"——实测**电机干扰只有 ~4% 磁场 / ~3.6° 航向，可忽略**。

真正让磁航向剧烈跳变的，是**外部铁磁体**（手机磁铁/NFC），不是电机。

---

## 二、关键发现一：磁力计数据"冻结"（已修复）

### 2.1 现象

磁力计三轴读数在任意工况下**一个 LSB 都不变**：

- 静止 3 秒采 214 帧，`mag_x/y/z` 恒为 `21.0 / 15.2 / -46.3 µT`
- 四电机满功率、单轮逐开，读数依然纹丝不动
- 对照：同一窗口加速度计 147 种取值、陀螺仪 178 种 → 证明整条 I2C 和传感器都在正常出数，只有磁力计冻住

### 2.2 根因

AK8963 磁力计的数据手册硬性要求：**每次读完数据必须再读 ST2(0x09) 寄存器**，否则内部锁存不解除、DRDY 不再置位，后续永远读不到新数据。

固件 `mpu9250.c` 的读取序列漏了这一步：

```c
/* 原代码（有 bug） */
if (AK_ReadReg8(AK8963_REG_ST1, &st1) == HAL_OK && (st1 & 0x01)) {
    uint8_t m[6];                                    /* HXL~HZH 6 字节 */
    if (AK_ReadReg(AK8963_REG_HXL, m, 6) == HAL_OK) {   /* ← 只读 6 字节，没读 ST2 */
        ...
    }
}
```

结果：开机第一次读到真实地磁（21/15/-46 µT，总强度 ~54 µT，符合北半球），此后 ST2 从未被读走 → 磁力计锁死 → `last_mag` 缓存永远回传这组初始值。

**这也解释了**为什么旧文档（`code-study/10-阶段复习` 等）会得出"电机干扰 40~60 倍"的错误结论：数据一直冻结成首帧值，怎么开电机都不变，于是误判为"干扰大到磁力计被完全淹没"。

### 2.3 修复（v3.3-MAGFIX）

| 文件 | 改动 |
|---|---|
| `mpu9250.h` | 补 `#define AK8963_REG_ST2 0x09` |
| `mpu9250.c` | 读缓冲 `m[6]`→`m[7]`，一次读 `HXL~ST2` 共 7 字节，读走 ST2 解锁 |
| `ota.h` | 版本 `v3.2-CFIX` → `v3.3-MAGFIX` |

HXH/HYL/HYH/HZL/HZH 之后紧跟 ST2(0x09) 连续排布，读 7 字节自然把 ST2 读走，末字节丢弃不影响解析。

## 三、关键发现二：电机干扰极小（推翻"40~60 倍"）

### 3.1 分阶段对照实验（无外界磁铁）

前 50 秒每 10 秒加一个轮子，各采 10 秒磁力计数据：

| 阶段 | 磁场强度 \|B\| (µT) | 磁航向 |
|---|---|---|
| 无轮 | 54.1 ± 0.7 | 310.4° ± 1.4° |
| M1（左前） | 53.2 ± 0.8 | 308.6° ± 1.7° |
| M1 + M3（+左后） | 53.0 ± 0.8 | 307.2° ± 1.8° |
| M1+M2+M3（+右前） | 51.8 ± 0.8 | 306.8° ± 2.0° |
| 四轮全开 | 转入旋转阶段 | — |

**趋势**：轮子越多，磁场强度 **54.1 → 51.8 µT（-4%）**，航向 **310.4° → 306.8°（-3.6°）**，单调、平滑、无跳变。

### 3.2 满占空比极端测试

| 工况 | \|B\| (µT) | 磁航向 |
|---|---|---|
| 全停 | 54.5 ± 0.7 | 308.3° ± 1.4° |
| 四轮满功率 DUTY=1.0 | 50.0 ± 0.7 | 305.5° ± 1.9° |

满功率（最恶劣）也仅 **|B| 掉 8%、航向偏 3°**。

### 3.3 旋转追踪验证

| 工况 | 结果 |
|---|---|
| 轮子停 + 转车身一圈 | 磁航向平滑追踪整圈（-382°）✅ |
| 四轮转 + 转车身一圈 | 陀螺 gz 积分精确 **360.0°** 判满 ✅ |

## 四、干扰源辨析：手机 vs 电机

做"电机转 + 转车身"的实验时，磁航向出现两次剧烈跳变（如 `284°→210°→309°`、`330°→216°→316°`）。

**复查发现**：这是测试者**故意用手机靠近磁力计**（手机磁铁/NFC）造成的，共 2~3 次，数据里跳变次数正好 2~3 次吻合。

同一实验里，跳变**之外**的平滑段，磁航向基线稳定在 ~310° 附近，与分阶段实验的"电机只偏 3~4°"完全一致。

> **结论**：电机干扰小到可忽略（~4% / ~3.6°）；真正让磁航向剧烈跳变的是**外部铁磁体**（手机、钥匙、铁架、NFC），这是任何磁力计都躲不过的物理现象，不是本项目缺陷。

---

## 五、最终结论

1. **磁力计可用性：乐观。** 电机干扰 ~4% 磁场 / ~3.6° 航向，工程上可忽略。
2. **唯一约束**：磁力计旁边不能有手机/铁磁体。真实巡检场景车自主行驶，此约束天然满足。
3. **历史修正**：旧文档"电机干扰 40~60 倍"是建立在磁力计冻结死数据上的误判，**作废**。

## 六、遗留技术债（待后续处理）

1. **欠标定**：`ahrs.c` 的 `MagHeadingDeg` 轴映射（IMU 绕 z 转 90° 换轴）只在注释里，未实测标定。
2. **磁偏角未设**：`MAG_DECLINATION` 当前 `0.0f`，邯郸约 **-5.7°**（偏西）。
   → ⚠️ 但见下文第 6.1 节：**磁偏角对本项目是无效改动**，不必改。
3. **死宏**：`odometry.c:59-61` 的 `ODOM_MAG_JUMP_RAD` / `ODOM_MAG_HIGH_GYRO_RADPS` / `ODOM_MAG_DIFF_WARN_RAD` 三个宏无任何引用，是半成品。
4. **校准不持久**：`MPU9250_CalibrateMag` 结果掉电丢失。
5. **磁力计判圈精度受工况影响大**：见第 6.2 节。

### 6.1 磁偏角对本项目无效（纯数学结论）

磁偏角是加在磁航向上的**加法常量**（`atan2(-mx,my) ± declination`）。本项目是**相对世界系**（开机朝向 = 0 = 北），不认"地理真北"，因此：

- 任何"差值类"计算（判圈累积、电机干扰前后对比）中，这个常量在两头**互相抵消**；
- 它唯一能修正的"绝对真北朝向"，本项目用不上。

> **结论**：`MAG_DECLINATION` 设 0 还是 -5.7°，对里程计、导航、判圈**均零影响**。此技术债可划掉。
>
> ⚠️ 论证时**禁止**用"陀螺转 360° 精确停"去佐证"磁偏角无关"——那是陀螺数据，与磁偏角无关。
> 磁力计、陀螺仪是两条独立链路，论证其一时绝不拿另一个佐证。

### 6.2 为什么"早期测磁力计完美、后期测偏差大"

历次测试对比：

| 轮次 | 判圈来源 | 电机 | 转法 | 干扰 | 结果 |
|---|---|---|---|---|---|
| ① 15:19 | 磁力计 | 全停 | 匀速 | 无 | -382°（平滑） |
| ③ 16:08 | 磁力计 | 全停 | 手转 | 无 | -489°（脚本静止噪声 bug） |
| ④ 16:16 | gz | 四轮转 | 一圈+1/4 | 无 | 502.6°（多转） |
| ⑤ 16:28 | 磁力计 | 四轮转 | 非匀速+卡顿 | 无 | -402°（折返假象） |

**三个决定"完美 vs 偏差"的条件**：

1. **电机转不转**（最大变量）：全停时磁航向干净；四轮转时每帧叠加 ±2° 抖动，长时间累加被放大。
2. **转得匀速否、有无卡顿**：卡顿时磁航向在局部来回抖，相位解缠把噪声误当转动累加。
3. **阈值 + 脚本**：早期阈值 340° 宽松，掩盖了 22° 偏差；后期严格 360°，脚本还带过多版 bug。

**本质结论**：

- 磁力计的**强项**是"报绝对朝向"（车头现在指哪）——第①轮已证明；
- 磁力计的**弱项**是"累计转了多少度（角度积分）"——每次采样带 ±2° 噪声，累加几百帧必漂。
- 所以"早期完美"是「轮子停 + 匀速 + 无干扰 + 宽松阈值」四个有利条件凑齐的结果；
  "后期偏差"是「电机转 + 非匀速卡顿 + 严格阈值」叠加恶化，**不是磁力计变差了**。
- 数圈/角度积分应当用**陀螺**（上一轮 gz 精确 360.0° 就是它的本职），磁力计只做**慢速绝对朝向校正**。

### 建议的磁力计接入方案

既然实测电机干扰可忽略，磁力计可以在"报朝向"上可靠工作：
- 静止时（ZARU 同款判定）把航向漂移拉回磁北；
- 运动中做低频慢速的绝对朝向融合（互补滤波），加手机/铁磁体野值剔除；
- **不要**用磁力计做高精度角度积分/圈数计数（那是陀螺的活）。
