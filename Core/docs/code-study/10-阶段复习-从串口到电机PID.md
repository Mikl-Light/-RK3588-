# 10 · 阶段复习：从串口到电机 PID（单片机侧 前三站）

> 这份文档是 **09（串口收发驱动）** 之后的压缩版回顾，覆盖 **串口 → 传感器航向 → 电机 PID** 三站。

> 读法：每节先看「它负责回答什么问题」，再看「关键数字」，最后才对行号。

---

## 0. 一站到底学的是什么

单片机侧只干四件事，我们讲完了前三件：

| 站 | 模块 | 它负责回答的问题 | 状态 |
|---|---|---|---|
| 1 | `uart_io.c` | 电脑说的话怎么进到芯片里，芯片的话怎么发出去 | ✅ 已讲 |
| 2 | `mpu9250.c` + `ahrs.c` | 车怎么知道自己是朝哪个方向的 | ✅ 已讲 |
| 3 | `pid.c` + `motor.c` | 怎么让轮子按指定的速度转 | ✅ 已讲 |
| 4 | `chassis.c` | 怎么让车往前走 / 横着走 / 原地转 | ⬜ 未讲 |

主循环一圈（10ms）里四个模块的顺序是固定的：

```
AHRS_Update  →  Odom_Update  →  Chassis_Update  →  Motor_UpdateAll
  算航向          算位置           算轮速            稳转速
```

后面每一步都吃前一步的输出，所以**读代码的顺序不能反**。

## 1. 第一站 · 串口收发（骨架）

### 它是什么
**两块仓库 + 一个搬运工 + 两个进出门。**

| 角色 | 是谁 | 特点 |
|---|---|---|
| 仓库 | `rx_buf` / `tx_ring` | 被动，放着就放着 |
| 放货的人 | 主循环 `PutChar` / 中断 `RxCallback` | 往里塞 |
| 搬运工 | DMA（只在发送侧） | 主动，但不叫它就不动 |

**收发两侧是镜像的**：结构完全一样，只是"谁在干活"换了人。
接收：外部 → 中断 → 仓库 → 主循环取。
发送：主循环 → 仓库 → 搬运工（DMA）→ 外部。

### 关键数字

| 数字 | 含义 | 出处 |
|---|---|---|
| 460800 | 波特率 | `uart_io.c` 初始化 |
| 21.7 µs | 一个字节在线上占的时间 | 460800 ÷ 10 位 |
| 460 | 10ms 内最多会进来多少字节 | 460800 ÷ 10 × 0.01 |
| **256** | 接收仓库格数 | `uart_io.h` `UART_RX_BUF_SIZE` |
| **2048** | 发送仓库格数 | `uart_io.h` `UART_TX_RING_SIZE` |
| 20 ms | 发送仓库满了等多久，超时就丢 | `uart_io.c` `PutChar` |

### 三处关键差异（最容易混）

| | 接收 RX | 发送 TX |
|---|---|---|
| 判满 | `rx_full` 标志 | **留一格空着** |
| 满了丢谁 | **最老的**（保时效） | **新来的**（保实时） |
| 关中断 | **要** | **完全不要** |

这三条是一条因果链：**留一格 → `head == tail` 只表示空 → 不需要 `tx_full` → 没有共写变量 → 不用关中断。**

### 两条铁律
1. **谁做"读-改-写"，谁就关中断。**
2. **满了丢谁，取决于"谁没得选"**：中断手里那个丢不掉，只能丢最老的；主循环那个还没放，放弃最省事。

### 必须清掉的误解
- 仓库**不减少中断次数**，它只决定能存多少。300 个字节 = 300 次中断，仓库改 10000 格也一样。
- DMA **不是绕过 CPU**，是 CPU 把搬货外包出去；启动那一次仍然要 CPU 出面。
- 接收侧**也能用 DMA**（循环模式 + 空闲中断），本项目没用，因为命令长度不固定。

## 2. 第二站 · 航向（陀螺 → 零偏 → 积分 → ZARU）

### 它是什么
**车其实不知道"我朝哪"，它是记账记出来的。**

陀螺仪测的不是方向，是**转得多快**（单位 °/s）。
方向靠累加：**这一圈转了多少 = 转速 × dt，加到上一次的航向上。**

### 三步流水线（`ahrs.c` `AHRS_Update`）

| 步骤 | 代码 | 干什么 |
|---|---|---|
| ① 读陀螺 | `ahrs.c:136` `MPU9250_ReadGyro` | 拿到 `gz`（绕竖直轴的转速） |
| ② 存原始值 | `ahrs.c:149` `gz_raw = gz` | 留给 ZARU 用 |
| ③ 减零偏 | `ahrs.c:150` `gz -= gyro_z_offset` | 把"静止时的假读数"扣掉 |
| ④ 积分 | `ahrs.c:157` `gyro_yaw = yaw_deg + gz * dt` | 这一圈转了多少加上去 |
| ⑤ 归一化 | `ahrs.c:159-160` | 折回 0~360（用两个 while，不能用 `%`） |

**`dt` 是实测的**，不是硬编码 0.01——主循环晚了就按实际时间算，所以被打断只会变慢，不会算错。

### 零偏（这一课的头号敌人）

> **零偏：车一动不动，陀螺仪却报出一个很小的非零数。**

**它可怕在会被积分：** `0.3 °/s` × 600 秒 = **180 度**。车静止放 10 分钟，"以为"自己掉了个头。

开机校一次（`GYROCAL` → `AHRS_RecalibrateGyro`），原理是：**车静止时真实转速为 0，所以读数全是误差。**

### ZARU（静止时偷偷重校零偏）

> **Zero Angular Rate Update：车每次真的停下来，就趁机把零偏重新量一次。**

为什么需要：零偏会随**温度**缓慢漂移，开机量的那份半小时后就不准了。

三道门槛**必须同时满足**（`ahrs.c:197-203`）：

| 门槛 | 值 | 防什么 |
|---|---|---|
| ① 编码器每轮 < 1 RPM | `ZARU_STATIONARY_RPM` | 常规判断"停没停" |
| ② 静止持续 ≥ 1000 ms | `ZARU_SETTLE_MS` | 刚停下还在惯性晃动 |
| ③ \|残余角速度\| ≤ 8 °/s | `ZARU_MAX_RESIDUAL_DPS` | **兜底：用陀螺仪自己判断** |

> ⚠️ `ahrs.c:195` 的注释写"≤3°/s"，代码是 **8.0f**。以代码为准。

校正方式**不是赋值**，是慢速低通（`ahrs.c:205-207`）：

```c
float k = dt / ZARU_TAU_S;                /* 0.01 / 2.0 = 0.005 */
if (k > 0.1f) k = 0.1f;                   /* dt 异常时防单次改太多 */
gyro_z_offset += (gz_raw - gyro_z_offset) * k;
```

**每 10ms 只补 0.5%。** 为什么不敢直接赋值：一次误判就会把零偏永久改坏，之后每一轮都拿它去减。

**tau 是什么**：从开始校正算起，经过 tau 这么长时间，差距被消掉约 2/3。
tau=2s → 每次补 0.5%；tau=0.2s → 每次补 5%（追得快，但抗误判能力差 10 倍）。

### 磁力计：默认是关的
`ahrs.c:100` `mag_fusion_enabled = false;`——整个工程只有 `AHRSMAG,ON` 能打开。
原因：电机磁场干扰是地磁的 **40~60 倍**。
所以 `ahrs.c:162-186` 那 25 行互补滤波（α=0.98）**开机后从来没执行过**，实际跑的是纯陀螺积分。

> 读码习惯：**看到一段精妙的算法，先问一句"它真的被执行了吗"。**

## 3. 第三站 · 电机与 PID

### 它是什么
**你说"轮子转 60 RPM"，它保证轮子真的转 60 RPM。**
它不关心车往哪走，只负责把轮子转速稳定在目标值。

### 为什么必须闭环
占空比 ≠ 转速。同一个 60% 占空比，电池掉压会变慢、地毯上会变慢、四个电机摩擦各不同。
**开环 = 我给了个数，剩下全看环境；闭环 = 我定目标，它自己调到目标。**

### 反馈从哪来：编码器

| 数字 | 含义 |
|---|---|
| 13 PPR | 编码器盘一圈的刻度数（电机轴） |
| **52** | 程序里的一圈计数 = 13 × 4（正交解码，A/B 两相各 4 个边沿） |
| **30** | 减速比：电机轴转 30 圈，轮子才转 1 圈 |

换算四步（`motor.c:200-204`）：

```c
float speed_counts_per_sec = (float)delta / dt;                        /* ① 格/秒 */
float motor_shaft_rpm = (speed_counts_per_sec * 60.0f) / (float)m->encoder_cnt_per_rev
                        * m->direction_sign;                           /* ② 电机轴 RPM */
m->speed_rpm = motor_shaft_rpm / m->gear_ratio;                        /* ③ 轮子 RPM */
```

> 为什么要换成"轮子口径"：因为目标 `60 RPM` 说的是轮子。不换算就是拿两个不同单位在比。

16 位计数器会回绕，`motor.c:171-175` 用 ±32767 判断并补 65536。

### 增量式 PID

> **它不算"输出应该是多少"，只算"这一轮该加多少"。**

`pid.c:84-97`：

```c
float p_term = pid->Kp * (error - pid->prev_error);                    /* P：误差变了多少 */
float i_term = pid->Ki * error * dt;                                   /* I：误差本身有多大 */
float d_term = pid->Kd * (error - 2*prev_error + prev2_error) / dt;    /* D：误差变多快 */
float output = pid->prev_output + p_term + i_term + d_term;            /* 上一轮 + 增量 */
```

参数（`motor.c:105`）：**Kp=0.001  Ki=0.015  Kd=0.00001**

**Ki 是 Kp 的 15 倍**，因为：误差稳定时 `Δe = 0`，P 项完全不出力，**消掉稳态误差全靠 I 项**。D 项因编码器噪声大而压得极低。

### 天然抗饱和（选增量式的理由）

位置式有积分累加器：输出撞到 100% 上限了，积分器还在傻累。
车卡墙 2 秒后松开，虚高的积分要很久才退回来，**这期间车会猛冲**。

增量式**没有累加器**：积分效应藏在 `prev_output` 里，而 `prev_output` 被限幅锁死。**限幅顺便把积分也限住了。**

### 四个电机的两个补偿维度

`motor.c:86-89`，两个维度**相互独立**，必须分别实测：

| 电机 | `direction_sign` | `invert_dir` | 含义 |
|---|---|---|---|
| M1 左前 | REVERSE | false | 仅编码器 A/B 反 |
| M2 右前 | FORWARD | false | 硬件完全正常 |
| M3 左后 | **REVERSE** | **true** | 编码器反 + 引线反 |
| M4 右后 | FORWARD | true | 仅引线反 |

- `direction_sign` = **编码器计数方向**（读数符号对不对）
- `invert_dir` = **PWM 转向**（轮子实际转的方向对不对）

**为什么 M3 两个都反反而读数看起来"正常"**：配置反 × 硬件反 = 抵消，但**原因不同**，不能只看现象就下结论。

### `PID_Reset` 是一个真实 bug 的现场

`pid.c:62-68` 三行：

```c
pid->prev_output = pid->output;              /* ① 输出不归零：保住现在的力度 */
float error = pid->setpoint - measurement;    /* ② 用"现在"算一次误差 */
pid->prev_error  = error;                     /* ③ 把历史写成这个误差 */
pid->prev2_error = error;
```

`Core/docs/pid-oscillation-fix.md` 记录了修复前的写法——误差历史直接清零，等于告诉控制器"上一瞬间误差是 0，现在突然 300"：

| 项 | 清零历史 | 写入当前误差 |
|---|---|---|
| P 项 | `0.001 × (300−0)` = **+0.30** | `0.001 × (300−300)` = **0** |
| D 项 | `0.00001 × (300−0+0)/0.01` = **+0.30** | `0.00001 × (300−600+300)/0.01` = **0** |
| I 项 | +0.045 | +0.045 |
| **合计** | **+0.645（占空比 64.5%）** | **+0.045（占空比 4.5%）** |

**10 毫秒内占空比从 0 跳到 64.5%，然后下一轮被砸到 −4%，电机原地抖。**

> 一行之差：清零 = 假装误差是突变来的；用当前值 = 承认误差一直都在。

## 4. 三个量必须分清（高频错点）

| 量 | 定义 | 车静止、目标 300 时 |
|---|---|---|
| **实测** `measure` | 编码器报出来的转速 | 0 |
| **误差** `e` | `setpoint − measure`，每轮重算 | **300（一直是 300）** |
| **误差的变化** `Δe` | 这一轮的 e 减去上一轮的 e | **0** |

**P 项和 D 项看的是"误差的变化"，I 项看的是"误差本身"。**

常见混淆：
- ❌ "车没动所以误差是 0" → 错，**车没动误差最大**（300）。
- ❌ "编码器突变导致 D 项有值" → 错，**D 项公式里根本没有编码器**，只有三个误差。
- ❌ "0 就是误差" → 0 是 `Δe`。

## 6. 自测题（分三层）

### 基础层（能答上说明读过）

1. 接收仓库满了，代码丢哪一头的数据？为什么？
2. 发送仓库满了，`PutChar` 丢哪一头？为什么和接收侧相反？
3. 航向从 `355°` 转 `+12°`，归一化后等于多少？

### 理解层（能答上说明读懂了）

4. 为什么发送侧一个 `__disable_irq()` 都没有，接收侧却必须关中断？
5. 车静止，陀螺仪读 `0.3 °/s`，这个数叫什么？放着 10 分钟会有什么后果？
6. ZARU 为什么要设三道门槛，而不是只看编码器？
7. 目标 60、实测 55，误差恒为 5 连续几十轮不变。P 项、D 项、I 项各贡献多少？谁在消掉这 5？

### 迁移层（能答上说明真懂了）

8. 位置式 PID 在车卡墙 2 秒后会猛冲，增量式为什么不会？
9. 编码器坏了永远读 0，你发 `M1,60`，PID 会让 PWM 怎么变？为什么停不下来？
10. D 项本该是 0，为什么把误差历史清零后它变成了 +0.30？它看到的"变化"是谁的变化？

### 参考答案

1. **最老的。** 中断手里那个字节丢不掉，接都接了，只能腾位置给新的（保时效）。
2. **新来的。** 主循环还没放进去，放弃手上这个最省事，而且主循环 10ms 必须转一圈，不能为了发日志卡住（保实时）。
3. `355+12 = 367`，减 360 → **7°**。
4. 发送侧 `tx_head` 只有主循环写、`tx_tail` 只有 DMA 完成中断写，**变量各有各的主人**。接收侧 `rx_tail` 两边都会写（中断满了丢最老时也动它），必须关中断保护读-改-写。
5. **零偏。** 会被积分：`0.3 × 600 = 180°`，车静止 10 分钟"以为"自己掉了头。
6. ①②靠**车轮**判断停没停，③靠**陀螺仪**判断。两个独立来源都说"停了"才可信；只看编码器会在打滑/被推时误判。
7. P = 0（`Δe`=0），D = 0（二阶差分 `5−10+5`=0），I 项 = `0.015 × 5 × 0.01 = 0.00075`。**全靠 I 项。**
8. 位置式的积分累加器在卡住期间一直涨（它不知道输出已被限幅挡住），松开后输出远大于 100%，要等误差变负才回落。增量式没有累加器，积分效应藏在被限幅锁死的 `prev_output` 里，**没有额外的账本就没有额外的欠账**。
9. 误差恒为 60，PID 每轮加 PWM，撞到 100% 上限卡住，轮子全速。**反馈断了，闭环变成闭着眼开环，而且它以为还没到目标。**
10. 变的是**误差的历史记录**：`prev_error/prev2_error` 被写成 0，等于骗控制器"上一轮误差是 0"，于是它看到 **0 → 300 的阶跃**。编码器读数全程没变（一直是 0）。
