# 09 · 串口收发驱动 `uart_io.c`

> 本文是 `Core/Src/uart_io.c`（346 行）的完整学习笔记，接在 01~08 之后。
> 用法：当字典查，不要通读。第 8 节有自测题，答不上来再回头看对应章节。

---

## 0. 一句话总纲

> **接收 = 中断"飞快地接住"，主循环"慢慢地吃"。**
> **发送 = 主循环"慢慢地放"，搬运工（DMA）"飞快地搬"。**
> 中间的仓库（环形缓冲区）让两边互不打扰。

---

## 1. 硬件与关键数字

| 项目 | 值 | 出处 |
|---|---|---|
| 串口 | USART2，PD5=TX / PD6=RX | `uart_io.h:9` |
| 波特率 | 460800，8N1，无流控 | 同上 |
| 每字节耗时 | **21.7 µs**（460800 ÷ 10 位 = 46080 字节/秒） | 计算 |
| 主循环周期 | **10 ms**（`HAL_Delay(10)`，`main.c:354`） | 实测/代码 |
| 10ms 内最多挤进来 | **460 字节** | 46080 × 0.01 |
| 接收仓库大小 | **256 格** | `UART_RX_BUF_SIZE`，`uart_io.h:28` |
| 发送仓库大小 | **2048 格**（实际能用 2047） | `UART_TX_RING_SIZE`，`uart_io.h:30` |
| printf 暂存 | 512 字节 | `UART_TX_BUF_SIZE`，`uart_io.h:29` |
| 发送满时最多等 | **20 ms**，等不到就丢这个字节 | `TX_BLOCK_WAIT_MS`，`uart_io.c:31` |
| FlushTx 超时 | **200 ms** | `TX_FLUSH_TIMEOUT_MS`，`uart_io.c:32` |

**两个数字的关系（最容易被问到）**：
460 是"10ms 内**会进来**多少"，256 是"**能装**多少"。
460 > 256 → 溢出时**前 204 个被顶掉，只剩最近到达的 256 个**。

> 实际很少溢出：一条 `V,0.3,0,0\r\n` 只有 12 字节，260 µs 发完。

## 2. 三个角色（全套比喻，务必记住）

| 角色 | 是谁 | 特点 |
|---|---|---|
| **仓库** | `rx_buf` / `tx_ring` | **被动**。东西放着就放着，不会自己动 |
| **放货的人** | 主循环（`PutChar` / `RxCallback` 的调用方） | 往仓库里塞字节 |
| **搬运工** | DMA（DMA1 Stream6） | **主动**干活，但你不叫它，它就不动 |

⚠️ **不要用"传送带"这个词**——"传送带"会让人以为东西会自己往前走，
从而误以为"仓库 + DMA 是一套自动机构"。**仓库和搬运工是两回事。**

---

## 3. 名词对照（重要）

英文 `head` / `tail` **没有全球统一约定**，教科书常见"tail 入队、head 出队"，
**和本项目正好相反**，所以不要从词义去推，只记角色：

| 代码里的名字 | 中文别名 | 含义 | 谁在动它 |
|---|---|---|---|
| `rx_head` | 进货口 | 下一个字节往哪格放 | 中断（ISR） |
| `rx_tail` | 出货口 | 下一个字节从哪格取 | 主循环 **和** 中断 |
| `tx_head` | 进货口 | 下一个字节往哪格放 | 主循环 |
| `tx_tail` | 出货口 | 下一个字节从哪格搬 | DMA 完成中断 |

**一条规则管两侧**：
> `head` = **往里放**的那一端（进货口）
> `tail` = **往外拿**的那一端（出货口）

## 4. 接收侧（四段，约 40 行核心）

### 段 1 · 造仓库（`uart_io.c:19-22`）

```c
static uint8_t  rx_buf[256];
static volatile uint16_t rx_head = 0;
static volatile uint16_t rx_tail = 0;
static volatile bool     rx_full = false;
```

**`volatile` 是什么**：告诉编译器"这变量可能被中断偷偷改掉，每次都要真去内存读，
不许优化到寄存器里"。没有它，"主循环里看起来不变的变量"会被编译器优化死。

### 段 2 · 中断里放货（`uart_io.c:282-296`）

```c
if (rx_full) rx_tail = (rx_tail + 1) % UART_RX_BUF_SIZE;  /* 满了 → 挤掉最老的 */
rx_buf[rx_head] = byte;
rx_head = (rx_head + 1) % UART_RX_BUF_SIZE;
if (rx_head == rx_tail) rx_full = true;
```

- **"丢老留新"在这里完成**：满了的时候两个指针撞在同一格，那格里装的就是最老的字节，
  新字节写进去，覆盖动作本身就把最老的销毁了。
- **为什么要挪 `rx_tail`**：不是为了触发丢弃（丢弃已经发生了），
  而是为了**让出货口仍指向"下一个最老的"**。不挪的话，主循环会先读到最新的字节，顺序颠倒。
- **它不需要关中断**：它本身就是中断，主循环没资格打断它。
  USART2 优先级 0（`uart_io.c:90`），没有更高的能插队。

### 段 3 · 主循环取货（`uart_io.c:235-249`）

```c
bool UART_IO_GetChar(uint8_t *ch)
{
    bool got = false;
    __disable_irq();
    if (rx_head != rx_tail || rx_full) {
        *ch = rx_buf[rx_tail];
        rx_tail = (rx_tail + 1) % UART_RX_BUF_SIZE;
        rx_full = false;
        got = true;
    }
    __enable_irq();
    return got;
}
```

**为什么要关中断**：`rx_tail = (rx_tail + 1) % 256` 在 CPU 上是**三步机器指令**
（读 → 加 → 写回）。中断可能插在中间，也改一次 `rx_tail`，主循环回来把旧值写回去，
**中断那次修改就白做了**。关中断就是把这三步锁住。

**函数签名里的 `uint8_t *ch`**：`return` 只能回一个值（成功没成功），
第二个值（字节内容）靠**地址**写回调用者的变量里。

### 段 4 · 硬件敲门（`uart_io.c:301-321`）

```c
uint32_t sr = huart2.Instance->SR;      /* 先抄一份状态（后面还要用） */
if (sr & USART_SR_RXNE) {               /* RXNE = 收到一个字节 */
    uint8_t byte = (uint8_t)(huart2.Instance->DR & 0xFF);
    UART_IO_RxCallback(byte);
}
```

**这个函数代码里没有任何人调用它**，它由硬件触发：
芯片收到字节 → CPU 记住"我执行到哪"（压栈）→ 查**中断向量表**
（`startup_stm32f407xx.s:184`，USART2 = 第 38 项）→ 跳到这个函数 → 执行完跳回原处。
**所以函数名一个字母都不能改。**

- **SR**（状态寄存器）= 一排指示灯。`&` 在这里是**位与**，作用是"只看 RXNE 那一位，别的不关心"。
- **DR**（数据寄存器）= 一个格子。**读它 = 把字节端走。**

### 调用者（`main.c:259-274`）

```c
while (UART_IO_Available() > 0) {
    if (UART_IO_GetChar(&ch)) {
        if (ch == '\r' || ch == '\n') ParseCommand(cmd_buf);
        else cmd_buf[cmd_idx++] = ch;
    }
}
```

### 必须清掉的误解：仓库不减少中断次数

很多人会想："既然有仓库了，中断就不用一个字节来一次了吧？"——不是。

- **中断的次数由字节数决定**：来 300 个字节 → 进 300 次中断。把仓库从 256 格改成 10000 格，**还是 300 次**。
- **仓库管的是"放哪儿"（容量），中断管的是"怎么放进去"（一次一个字节，硬件定的）。**

用快递打比方：**柜子再大，快递员还是一件一件地送。**

仓库真正省掉的不是中断次数，而是**每次中断要干的事**：

| | 中断里做什么 | 耗时 |
|---|---|---|
| **有仓库** | 往仓库写一格内存，退出 | 几微秒 |
| **没仓库**（假想） | 必须当场把整条命令解析完、执行完 | 几十~上百微秒 |

主循环每 10ms 必须跑完一轮 PID + 里程计，所以**中断里绝不允许处理业务逻辑**，只允许"接住"。
仓库的价值就是把**接住**和**处理**在时间上拆开：中断负责飞快接住，主循环负责慢慢处理。

> **顺带一个常被误解的事实**：接收侧**也可以用 DMA**（DMA 循环模式 + IDLE 空闲中断）。
> 本项目没用，原因是**命令长度不固定**（`V,0.3,0,0` 与 `ODOSET,1.5,2.0,90` 不一样长），
> 而 DMA 必须提前告诉它搬几个字节。发送侧每帧长度是当场算出来的，所以能用。

## 5. 发送侧（六步）

```
① PutChar 放货       查仓库满没满 → 放入进货口那格 → 进货口前移
② 顺手喊一声 TxPump   每放一个字节都喊（uart_io.c:121）
③ TxPump 过两道关     搬运工到场且不忙？仓库不空？过不去就 return
④ 算一趟的量交出去    算 chunk → 写纸条 tx_dma_len → 挂牌 tx_dma_busy → 填提货单
⑤ 搬运工自己搬        一字节一字节写进 DR，串口自动推上线，CPU 不管
⑥ 搬完敲一下 CPU      照纸条前移出货口 → 摘牌 → 再喊一声 TxPump
```

### 为什么需要搬运工

CPU 自己发，每字节要**站着干等 21.7 µs**（`uart_io.c:104` 那个空转 `while`）。
一帧遥测 112 字节 → **2.4 ms 全程空转**，而主循环一圈才 10 ms。
DMA 就是把这个"等"外包出去。

### `PutChar`（`uart_io.c:100-122`）

```c
if (!tx_dma_ok) {                          /* DMA 挂了 → 回退成轮询硬发 */
    while (__HAL_UART_GET_FLAG(&huart2, UART_FLAG_TXE) == RESET);
    huart2.Instance->DR = (uint8_t)c;
    return;
}

uint32_t wait_start = HAL_GetTick();
while (((tx_head + 1) % UART_TX_RING_SIZE) == tx_tail) {   /* 满了吗 */
    if (HAL_GetTick() - wait_start >= TX_BLOCK_WAIT_MS) {
        tx_drop_count++;      /* 等 20ms 还不行 → 丢掉这个字节 */
        return;
    }
}

tx_ring[tx_head] = (uint8_t)c;
tx_head = (uint16_t)((tx_head + 1) % UART_TX_RING_SIZE);
UART_IO_TxPump();             /* 顺手喊一声 */
```

**判满式怎么读**：

| 片段 | 念作 |
|---|---|
| `tx_head + 1` | 如果我把这字节放进去，进货口会挪到这一格 |
| `% 2048` | 挪到头了就绕回 0 号格 |
| `== tx_tail` | 这一格，是不是正好是出货口站着的地方？ |

**只有问句，没有赋值**——它不挪任何东西，只问"会不会撞"。
（接收侧相反：先挪了再说，挪完看撞没撞。）

### 为什么发送仓库永远空一格（只能装 2047）

如果最后一格也填上，`head` 会绕回和 `tail` 重合 → `head == tail` 就同时表示"空"和"满"，
分不出来，就得像接收侧那样再加一个 `tx_full` 标志。

而**加了 `tx_full` 就要关中断**（它会被中断置真、被主循环置假，是共写变量）。

> **留一格 = 用 1 格空间，换掉了整把锁。**

接收侧没这么干，是因为它更在乎容量（256 格全用上）；
发送侧 2048 格，浪费 1 格眼都不眨。

### `TxPump`（`uart_io.c:179-204`）

**它是什么**：**看一眼仓库里有没有货。有，就叫搬运工来搬。**

**为什么是个独立函数**：因为它有**两个调用者**，逻辑要在两处用：

| 调用点 | 时机 |
|---|---|
| `uart_io.c:121` | `PutChar` 放完字节顺手喊 |
| `uart_io.c:212` | DMA 搬完一段，在完成中断里接着喊 |

**两道关卡（行 181、185）**：

```c
if (!tx_dma_ok || tx_dma_busy) return;   /* 搬运工到场了吗？忙着吗？ */
if (head == tail) return;                /* 仓库是空的吗？ */
```

有这两道门，上面两个调用点就可以**无脑乱叫**——重复叫、正忙时叫，都直接返回。
**所以真正启动 DMA 只有两个时刻：环里进第一个字节时、DMA 刚搬完一段时。**

**算这一趟搬几个（行 188-190）**：

```c
uint16_t avail = (uint16_t)((head - tail + UART_TX_RING_SIZE) % UART_TX_RING_SIZE);
uint16_t chunk = (uint16_t)(UART_TX_RING_SIZE - tail);
if (chunk > avail) chunk = avail;
```

| 变量 | 是什么 |
|---|---|
| `avail` | 仓库里**一共有几个货** |
| `chunk` | **这一趟能搬几个**（搬运工不会拐弯，到数组末尾就停） |

**那串 `+ N` / `% N` 的两步分工**：

| 步骤 | 只管什么 |
|---|---|
| `+ 2048` | **管负数**（进货口在出货口左边时要绕一圈） |
| `% 2048` | **管加过头**（本来没绕圈，`+2048` 后多出一整圈，要减掉） |

> **C 语言里 `-3 % 8` 的结果是 `-3`，不是 5。** 负数取模仍是负数，
> 所以必须先 `+N` 抬起再 `%N`。两步缺一不可。

**出发前两行（行 192-193）**：都是为了回来时用。

| 变量 | 出发前 | 回来时 |
|---|---|---|
| `tx_dma_len` | 写纸条：这趟搬几个 | 照纸条结账 `tx_tail += tx_dma_len` |
| `tx_dma_busy` | 挂牌：我忙了 | 摘牌 `= false` |

**没有 `tx_dma_len`，CPU 回来时不知道该把出货口往前挪几格**（不是挪 1 格，
是挪这一趟的长度）。

**提货单（行 195-198）**：

```c
HAL_DMA_Start_IT(&hdma_uart2_tx,                  /* 用哪个搬运工 */
                 (uint32_t)&tx_ring[tail],        /* 从哪儿搬 */
                 (uint32_t)&huart2.Instance->DR,  /* 搬到哪儿 */
                 chunk)                           /* 搬几个 */
```

**`&` 在这里是"取地址"，不是位与**（`uart.c` 里两种都用到了）：

- `&tx_ring[tail]` → 第 tail 格**在哪儿**（位置）← 搬运工要这个
- `tx_ring[tail]` → 第 tail 格里**装的那个数**（内容）

填错会怎样：假设那格装的是 `'A'`（ASCII 65），搬运工就跑去**65 号地址**搬货，
那是一片跟仓库无关的内存（中断向量表附近），串口上喷出一堆垃圾。

**为什么编译不报错**：`(uint32_t)` 是合法类型转换。
**C 编译器只检查类型，从不检查"这个数是不是真的有效地址"。**

**DR 的两种用法（都不带 `&`）**：

```c
uint8_t byte = huart2.Instance->DR;   /* 读 = 把收到的字节端走 */
huart2.Instance->DR = (uint8_t)c;     /* 写 = 把这个字节送出去 */
```

两行要的都是 DR 的**内容**，不是位置，所以不需要 `&`。

### 完成回调（`uart_io.c:207-213`）

```c
static void UART_TxDmaCplt(DMA_HandleTypeDef *hdma)
{
    tx_tail = (uint16_t)((tx_tail + tx_dma_len) % UART_TX_RING_SIZE);  /* 结账 */
    tx_dma_busy = false;                                               /* 摘牌 */
    UART_IO_TxPump();                                                  /* 接着搬下一段 */
}
```

**最后一句是这套机制的精髓**：搬完一段自动叫下一段，直到环里清空。
CPU 只在"每段搬完"时露一次面。

## 6. 收发对比（整篇的浓缩）

| 维度 | 接收 RX | 发送 TX |
|---|---|---|
| 谁产生数据 | 芯片硬件（来一个进一个） | 主循环（`PutChar`） |
| 谁消费数据 | 主循环（`GetChar`） | **DMA 硬件** |
| 仓库大小 | 256 | 2048 |
| 判满方式 | `rx_full` 标志 | **留一格空着** |
| 实际可用 | 256 | 2047 |
| 满了丢谁 | **最老的** | **新来的** |
| 谁写进货口 | 中断 | 主循环 |
| 谁写出货口 | 主循环 **和** 中断 | 基本只有中断 |
| 要关中断吗 | **要** | **完全不要** |

### 为什么两侧"满了丢的人"相反

不是"哪个更值钱"，而是**谁在执行丢弃**：

- **接收侧**：数据是外面塞进来的，接的人在**中断**里，字节已经在他手上了，拒绝不了。
  要腾位置只能牺牲**最老的**。
- **发送侧**：数据是自己放进来的，放不进时**放弃自己手上这个最省事**（不动指针，直接 `return`）。

更深一层，两侧保的东西不同：

| | 保什么 | 为什么 |
|---|---|---|
| 接收侧 | **时效** | 你发"停"，不能因为缓冲里有旧命令就把"停"丢了 |
| 发送侧 | **实时** | 主循环 10ms 必须转一圈，注释原文"防 DMA 异常时挂死主循环" |

### 为什么发送侧一个 `__disable_irq` 都没有

因为它做到"变量各有各的主人"：`tx_head` 只主循环写，`tx_tail` 只有完成中断写，
两边都不需要上锁。

> **谁和中断共用同一个变量，谁就要关中断把自己那几步锁起来。**
> 想不锁，就必须让变量各有各的主人。

### 参考答案

1. RX **256**，TX **2048**；实际可用 **256** 和 **2047**（TX 留一格判满）。
2. RX 丢**最老的**（时效性）；TX 丢**新来的**（不拖住主循环）。
3. 记下"这一趟搬了几个"，供 DMA 完成中断结账时把出货口一次前移这么多格（行 210）。
4. 因为发送侧**永远留一格不填**，`head == tail` 只可能表示空，不会表示满，
   所以不需要额外标志 → **也不需要关中断**。
5. `GetChar` 里 `rx_tail = (rx_tail + 1) % N` 是读-改-写三步，会被中断打断；
   `RxCallback` 本身就是中断，主循环没资格打断它，没人能插队。
6. 因为 `PutChar` 每放一个字节都会喊它。有这道门挡着，"白叫"变成零成本，
   调用点不用自己判断"我是不是第一个字节"。
7. 传给 DMA 的就变成"那个字节的内容"（0~255 的一个数）。DMA 会把它当地址，
   跑去那片内存搬 `chunk` 个字节发出去 → 串口上全是垃圾，报文一个字发不出。
8. **2**。数组下标是 **0~7**，没有第 8 格；从第 6 格走到末尾只有第 6、7 两格。
9. 仓库 8 格，18 个字符进来 → 前 10 个被顶掉，**只剩最后 8 个字符 `5,2.0,90`**。
   （注意：8 格全用满，因为接收侧用的是 `rx_full` 标志而不是留一格。）

## 9. 遗留的小坑（读代码时注意）

| 位置 | 现象 | 说明 |
|---|---|---|
| `uart_io.c:39/58/113` | `tx_drop_count` 只在自增和清零，**从没被读取** | 死代码。发送丢字节目前是**静默**的。想诊断可加个 `TXSTAT` 命令打出来 |

`UART_IO_FlushTx()` 全项目只被调用 4 次，都是"下一步要卡住 CPU，得先把话说出去"：
`main.c:580`(MAGCAL 前) / `main.c:611`(GYROCAL 前) / `ota.c:28`(擦 Flash 前) / `ota.c:51`(软复位前)。
**这是异步发送的代价：平时不等（所以快），但需要等的场合必须显式等一次。**
