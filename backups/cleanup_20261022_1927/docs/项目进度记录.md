## 二、固件校准机制查证（已确认）

### 上电时执行的校准
- **只做陀螺零偏校准**：`MPU9250_CalibrateGyro(500)`，静止采 500 样本求均值
- **没有磁力计校准**：上电不做任何 mag 校准

### 磁力计校准（手动触发）
- 命令：`MAGCAL,<ms>`，串口触发
- 方法：2D 平面 min/max 法，只校准 X/Y
- **参数不持久化**：存在 static 全局变量，断电丢失
- 固件有 `MPU9250_CalibrateMag()` 函数（`mpu9250.c:680`），但上电不调用

### AHRS 配置
- `mag_fusion_enabled = false`（默认关闭）
- 互补滤波 alpha=0.98（磁力计只占 2% 权重）
- **ZARU**：静止时（编码器全零）自动重估陀螺零偏
- I2C 连续 5 次失败自动降级为纯陀螺
- 磁偏角 `MAG_DECLINATION = 0`（邢台实际约 -6.7°）

## 三、里程计融合方案

### 背景（用户纠正）
- 用户**实际使用** `mecanum_bringup_hector/launch/laser_odom_mapping.launch.py`（纯激光里程计方案）
- **不用** `mecanum_bringup`（轮式里程计不准，建图重叠）
- `odom_compare_web` 是有意做的对比实验工具，两个 odom 不是冲突
- serial_bridge `publish_odom:=False`，只留 cmd_vel/IMU；rf2o 用 `odom_laser` 帧；slam_toolbox `odom_frame=odom_laser`

### 核心问题
轮式 yaw 漂移的根源 = **陀螺零偏残差**（一个恒定数值 b 一直在积分累加）。
用激光里程计 yaw 作为真值参考，在特征区在线估计 b；开阔区激光退化时，用估计出的 b 补偿轮式 yaw。

### 算法
```
特征区（scan 有效点 ≥ 25%，激光不陈旧）：
  diff(t) = wrap_pi(yaw_轮式 - yaw_激光)
  b = 5秒滑动窗口线性回归斜率(diff)   ← 陀螺零偏
  b_smooth = 低通(b, alpha=0.05)
  b_cumulative += b_smooth * dt
  yaw_修正 = yaw_轮式 - b_cumulative
  yaw_融合 = yaw_修正 + w * 0.1 * (yaw_激光 - yaw_修正)  ← 慢速修正

开阔区（scan 退化 或 激光陈旧 >0.5s）：
  w = 0
  yaw_融合 = yaw_轮式 - b_cumulative   ← 用已估计的零偏补偿，陀螺+编码器撑住
```

跳变剔除：单帧 diff 变化超过阈值则清空窗口（防止激光跳变污染估计）。

### 输入话题
| 话题 | 类型 | 来源 | 频率 |
|------|------|------|------|
| `/odom` | nav_msgs/Odometry | serial_bridge（轮式EKF） | 50Hz |
| `/odom_laser` | nav_msgs/Odometry | rf2o | 10Hz |
| `/imu/imu407/data_raw` | sensor_msgs/Imu | serial_bridge（gyro_z） | 50Hz |

### 输出话题
| 话题 | 类型 | 说明 |
|------|------|------|
| `/odom_fused` | nav_msgs/Odometry | 融合后里程计，50Hz，frame_id=odom_fused |
| `/fusion_diag` | std_msgs/String | JSON 诊断（b、w、yaw对比等14项） |
| TF | odom_fused→base_link | 融合后的坐标变换 |

### 可调参数（launch 文件）
| 参数 | 默认值 | 说明 |
|------|--------|------|
| `scan_valid_ratio_threshold` | 0.25 | scan 有效点占比低于此值→激光退化 |
| `laser_stale_sec` | 0.5 | 激光 odom 超过此时间未更新→退化 |
| `bias_window_sec` | 5.0 | 零偏估计滑动窗口长度 |
| `bias_min_trust` | 0.5 | 权重低于此值不估计零偏 |
| `bias_jump_reject_rad` | **0.3** | 跳变剔除阈值（⚠️ 已从0.05修复为0.3） |
| `bias_lowpass_alpha` | 0.05 | 零偏低通系数 |
| `laser_correction_gain` | 0.1 | 特征区激光 yaw 慢速修正增益 |
| `publish_tf` | true | 是否发布 odom_fused→base_link TF |

## 六、实车测试记录

### 测试1：启动失败（缺 setup.cfg）
- **现象**：`package 'odom_fusion' found, but libexec directory does not exist`
- **原因**：ament_python 包缺 `setup.cfg`，setuptools 不把可执行脚本装到 `lib/odom_fusion/`
- **修复**：新增 `setup.cfg`，内容：
  ```
  [develop]
  script_dir=$base/lib/odom_fusion
  [install]
  install_scripts=$base/lib/odom_fusion
  ```
- **状态**：✅ 已修复

### 测试2：启动成功但零偏估计 b=0
- **现象**：`/fusion_diag` 输出 `bias_b_deg_s: -0.0, bias_b_raw: 0.000`，零偏估计始终为0
- **原因**：跳变剔除阈值 `bias_jump_reject_rad = 0.05 rad (2.86°)` 太小。
  轮式 odom 50Hz、激光 odom 10Hz 异步，每次激光 yaw 更新时 diff 跳变超过 2.86°，
  触发窗口清空，窗口永远凑不够 1 秒，线性回归永不触发。
- **修复**：阈值改为 0.3 rad (17°)，正常激光更新跳变不会误触发
- **状态**：✅ 代码已修复，**尚未重新实车验证**

### 测试3：磁力计电机干扰实测
- **方法**：`ros2 topic echo /imu/imu407/mag`，对比静止和旋转时的读数
- **数据**：

| 阶段 | mag_x | mag_y | mag_z |
|------|-------|-------|-------|
| 静止 | 0.15 uT | 0.0 uT | -94.95 uT |
| 电机旋转 | 0.15 uT | 0.0 uT | **-2178 ~ -3118 uT** |

- **结论**：电机旋转时 z 轴磁力计读数翻了 **33 倍**（-95→-3100 uT），
  干扰是地球磁场（~50 uT）的 40~60 倍。
  用户之前用手机指南针测"没干扰"是因为手机有硬件低通+软件融合+距离远，
   raw 磁力计（AK8963）没有这些保护。
- **决策**：保持 `AHRSMAG OFF`，磁力计**只在开机电机未转时读一次**做初始朝向，
  运行时绝对不参与航向融合。
- **备注**：静止时 mag_x=0.15, mag_y=0.0 也可疑（邢台水平分量应~35uT），
  可能磁力计未校准或安装方向问题，但不影响运行时不用磁力计的决策。

## 八、关键技术决策记录

1. **不动用户原有代码**：新包 `odom_fusion` 完全独立，不修改 `mecanum_bringup`、`mecanum_bringup_hector`、`rf2o`
2. **odom_compare_web 可修改**：用户明确说这个包不重要，可以修改
3. **磁力计运行时不用**：电机干扰铁证如山，只用于开机初始朝向
4. **零偏在线估计而非写回固件**：先在上位机补偿，温度漂移自动跟踪；写回固件是后续可选优化
