# 问题排查与解决记录（2026-08-19 至今）

> 记录范围：ROS2 Jazzy 建图、导航、摄像头、键盘控制、STM32 固件上电问题  
> 平台：RK3588 + Ubuntu 24.04 + ROS 2 Jazzy（2024.04） + STM32F407 麦轮底盘  
> 说明：本文件只记录问题和解决过程，方便后续写论文/交接。

## 1. 建图阶段问题

### 1.1 ROS2 Jazzy 没有官方 hector_slam

**问题**：ROS2 Jazzy 官方 apt 没有 hector_slam / hector_mapping。

**解决**：
- 提供真 Hector launch，但说明需要自行安装 ROS2 移植版。
- 推荐先使用 `laser_odom_mapping.launch.py` 作为替代方案。

---

### 1.2 rf2o 激光里程计一直 “Waiting for laser_scans”

**问题**：`/scan` 有数据，但 rf2o 不收。

**原因**：
- rf2o 节点参数 `init_pose_from_topic` 默认是 `/base_pose_ground_truth`。
- 未把它设为空时，rf2o 会一直等待初始位姿。

**解决**：

```python
'init_pose_from_topic': '',
```

---

### 1.3 rf2o 参数名错误导致 TF 不发布

**问题**：rf2o 不发布 `odom_laser -> base_link` TF。

**原因**：
- 参数名应为：
  - `base_frame_id`
  - `odom_frame_id`
- 不是：
  - `base_frame`
  - `odom_frame`

**解决**：

```python
'base_frame_id': 'base_link',
'odom_frame_id': 'odom_laser',
'publish_tf': True,
```

---

### 1.4 map 坐标系不存在 / 地图不显示

**问题**：rviz2 报 `Frame [map] does not exist`。

**原因链**：
- `slam_toolbox` 未 active
- 或 rf2o 未输出激光里程计 TF
- 或 map_server 没有持续发布 `/map`

**解决**：
- 确认 slam_toolbox active：

```bash
ros2 lifecycle get /slam_toolbox
```

- 确认 TF：

```bash
ros2 run tf2_ros tf2_echo odom_laser base_link
ros2 run tf2_ros tf2_echo map odom_laser
```

---

### 1.5 Jazzy map_server 不主动发布 /map

**问题**：map_server active 后 rviz2 收不到地图。

**原因**：
- Jazzy 的 map_server 不会主动发 `/map`。
- 需要调用地图服务触发。
- 服务名是 `/map_server/map`，不是 `/map_server/get_map`。

**解决**：

```bash
ros2 service call /map_server/map nav_msgs/srv/GetMap "{}"
```

**进一步解决**：
- 编写 `map_trigger.py`：
  1. 调用 `/map_server/map`
  2. 以 1Hz 持续发布 `/map`
  3. 使用 `transient_local + reliable` QoS
  4. 自动调用 AMCL 全局重定位服务

---

### 1.6 map_trigger 在 spin 中再次 spin 导致崩溃

**问题**：

```text
RuntimeError: Executor is already spinning
```

**原因**：
- 定时器回调中调用了 `rclpy.spin_until_future_complete()`。

**解决**：
- 改为 `future.add_done_callback()` 异步回调。

---

### 1.7 地图保存命令找不到

**问题**：

```text
ros2 run slam_toolbox slam_toolbox_save_map
No executable found
```

**解决**：
- Jazzy 使用：

```bash
ros2 run nav2_map_server map_saver_cli -f ~/map/hector_compare
```

---

### 1.8 rviz2 保存按钮不是保存地图

**问题**：rviz2 关闭时点 Save，不知道地图存到哪里。

**说明**：
- rviz2 保存的是显示配置，不是地图。
- 地图必须用 `map_saver_cli` 保存。

---

### 1.9 地图发布频率 0.2Hz

**说明**：
- slam_toolbox 默认 5 秒发布一次 `/map`，即 0.2Hz，属正常。
- 可在 slam_toolbox 参数中设置：

```yaml
map_update_interval: 1.0
```

## 2. 摄像头问题

### 2.1 官方 v4l2_camera 不支持 MJPG

**问题**：MJPG 输出崩溃，YUYV 在 USB2.0 下带宽过大。

**解决**：
- 新建包 `tools/camera_bringup`
- 编写 `mjpeg_camera_node.py`
- 默认 MJPG 采集，发布 `/image_raw/compressed`
- 支持 640x480 / 1280x720 / 1920x1080

---

### 2.2 网页视频黑屏

**问题**：`web_video_server` 打开 `/image_raw` 黑屏。

**原因**：
- 相机节点最初只发 `/image_raw/compressed`。
- 后来发送 `/image_raw` 时使用了 BEST_EFFORT QoS。
- `web_video_server` 使用 RELIABLE 订阅，QoS 不匹配。

**解决**：
- `/image_raw` 使用默认 RELIABLE QoS 发布：

```python
self.raw_pub = self.create_publisher(Image, self.image_topic, 10)
```

## 3. 键盘控制问题

### 3.1 单独按 + / - 崩溃

**问题**：

```text
AttributeError: 'KeyboardTeleop' object has no attribute 'adjust_axis_speed'
```

**原因**：
- 原代码调用 `adjust_axis_speed()`，但方法名实际是 `adjust_speed()`。

**解决**：
- 新建 `keyboard_teleop_hector` 修复版。

---

### 3.2 SSH 下组合键不稳定

**说明**：
- SSH stdin 模式依赖终端自动重复字符流。
- W+D 等组合键可能不稳定。

**缓解**：
- 调大 `auto_stop_timeout`：

```bash
ros2 run mecanum_bringup_hector keyboard_teleop_hector \
    --ros-args -p input_mode:=stdin -p auto_stop_timeout:=0.5
```

- 本地键盘使用 evdev 模式最稳定。

## 4. 导航阶段问题

### 4.1 Nav2 Jazzy 包名/节点名变化

**问题**：
- `nav2_recoveries` 找不到
- `recoveries_server` 找不到

**解决**：

```text
包：nav2_behaviors
可执行文件/节点：behavior_server
```

---

### 4.2 插件名要使用 `::` 而不是 `/`

**问题**：

```text
Failed to create global planner:
nav2_navfn_planner/NavfnPlanner does not exist
```

**解决**：

```yaml
plugin: "nav2_navfn_planner::NavfnPlanner"
```

行为插件同理：

```yaml
plugin: "nav2_behaviors::Spin"
plugin: "nav2_behaviors::BackUp"
plugin: "nav2_behaviors::Wait"
```

---

### 4.3 local_costmap width/height 类型错误

**问题**：

```text
parameter 'height' has invalid type:
parameter {height} is of type {integer},
setting it to {double} is not allowed.
```

**解决**：

```yaml
width: 3
height: 3
```

不要写成 `3.0`。

---

### 4.4 bt_navigator 崩溃

**问题**：bt_navigator 进程 segfault。

**原因**：
- 手动指定的 `plugin_lib_names` 与 Jazzy 版本不匹配。

**解决**：
- 删除 `plugin_lib_names`，使用 Jazzy 内置默认列表。

---

### 4.5 AMCL 不发布 map -> odom_laser TF

**问题**：planner_server 激活时一直等 TF：

```text
Invalid frame ID "map"
```

**原因**：
- AMCL 没有配置 `odom_frame_id`。
- 默认找 `odom`，实际是 `odom_laser`。

**解决**：

```yaml
amcl:
  ros__parameters:
    odom_frame_id: "odom_laser"
```

---

### 4.6 多个 lifecycle 节点不自动 active

**问题**：
- planner/controller/behavior/bt 常停在 `inactive`。

**原因**：
- 旧节点重复，lifecycle_manager 连到错误节点或中途失败。
- planner 激活时 map TF 还没出现。

**解决**：
- 清理所有旧节点。
- 重启 ROS2 daemon。
- 必要时手动按顺序激活：

```bash
ros2 lifecycle set /map_server activate
ros2 lifecycle set /amcl activate
ros2 lifecycle set /planner_server activate
ros2 lifecycle set /controller_server activate
ros2 lifecycle set /behavior_server activate
ros2 lifecycle set /bt_navigator activate
```

---

### 4.7 在线 SLAM 导航方案

**问题**：AMCL 静态地图需要手动给初始位姿，且初始位姿给不准。

**解决**：
- 新增 `online_slam_navigation.launch.py`
- 使用 slam_toolbox 边建图边定位。
- 不需要 map_server，不需要 AMCL。
- 可由 map_trigger 自动调用 `/reinitialize_global_localization`。

---

### 4.8 导航只旋转不前进

**问题**：路径已规划，但车只缓慢左右摇摆。

**原因链**：
- 雷达扫描坐标与物理车头方向反了 180°。
- SLAM 地图认为目标在车后方。
- RPP 一直执行“转向对准目标”，所以只有 angular.z。

**验证方法**：
- 让车实际前进，观察 `/odom_laser` 的 x：

```text
车前进，odom x 变小 -> 方向反了 180°
```

**解决**：
- 静态 TF `base_link -> laser` 的 yaw 从 `0` 改为 `3.14159`：

```bash
--yaw 3.14159
```

---

### 4.9 rviz2 点目标点不触发导航

**原因**：
- rviz2 默认 `2D Goal Pose` 发布 `/goal_pose`。
- Nav2 只监听 `/navigate_to_pose` action。

**解决**：
- 新增 `goal_pose_bridge.py`：

```text
/goal_pose -> /navigate_to_pose action
```

---

### 4.10 导航到狭窄区域后停车

**当前现象**：
- 车进入狭窄区域后，不再移动。
- 命令行发目标也无法移动。

**可能原因**：
- 局部代价地图把两侧障碍膨胀后，控制器判定无安全通道，主动停车。
- 这是 Nav2 安全行为，不一定是里程计损坏。

**下一步建议**：
1. 用键盘把车退出狭窄区域。
2. 对比轮式 odom 和激光 odom。
3. 再决定是否切换为轮式里程计导航。
